# Разбор анализатора

1. Покажите три строки синтетического лога в `tests/sample/` и объясните, откуда
   parser берёт URL и время.
2. Запустите CLI по README и откройте отчёт. Для `/api/v1/products` должно быть
   два запроса и сумма времени 0.523 секунды.
3. Покажите `iter_logs`: генератор читает строки постепенно и считает долю ошибок.
4. Объясните, что `group_endpoints` всё же хранит все времена для медианы.
5. Найдите тест выбора последнего лога и тест сохранности старого отчёта при ошибке.
6. Объясните, почему содержимое URL записывается через `textContent`, а символ `<`
   экранируется до вставки JSON в HTML.

Самостоятельная задача, пока не реализована: предложить метрику p95. Сначала
объясните её смысл и договоритесь о формуле на коротком списке времён. Затем
добавьте вычисление, тест на известном наборе и столбец отчёта. Подумайте, изменится
ли потребление памяти, если одновременно нужна точная медиана.
